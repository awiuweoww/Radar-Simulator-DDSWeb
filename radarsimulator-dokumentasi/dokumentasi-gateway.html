6. Dokumentasi Gateway

Panduan teknis membangun jembatan biner antara OpenDDS dan WebSocket.

Setup & Instalasi

Gateway dirancang menggunakan Node.js dengan native binding node-opendds untuk performa bridging maksimal.

# 1. Masuk ke direktori gateway
cd gateway-ddsweb

# 2. Install dependensi Node.js
npm install

# 3. Build library biner dari IDL (Shared Object)
# Pastikan ACE/TAO environment sudah aktif
npm run build:idl

# 4. Menjalankan Gateway
# Merujuk ke file konfigurasi RTPS yang ada di folder backend
node server.js -DCPSConfigFile ../be-stream-odds-cpp/rtps.ini

Inisialisasi Server & OpenDDS

Gateway ini menggabungkan protokol HTTP (untuk REST API) dan WebSocket dalam satu server yang terintegrasi dengan OpenDDS.

1. Dependensi Utama

Menggunakan pustaka standar industri untuk menjamin keandalan:

  • opendds: Native binding untuk akses ke jaringan DDS.
  • express: Framework web untuk menangani REST API.
  • ws: Implementasi WebSocket untuk streaming data real-time.
  • http: Modul inti Node.js untuk menyatukan Express dan WS pada satu port.

2. Integrasi Server (Hybrid)

Kedua protokol berjalan berdampingan pada port 8080:

const app = express();
const server = http.createServer(app);
const wss = new WebSocketServer({ server });

Fungsi: initializeDDS()

Fungsi asinkron ini bertanggung jawab menyiapkan lingkungan DDS sebelum server mulai menerima koneksi:

Core Logic Line 138 - 151
  • opendds.load(): Memasukkan library biner IDL ke dalam memori aplikasi agar Gateway mengenal struktur paket data DDS.
  • getParticipant(0): Membuat entitas Domain Participant pada Domain 0 untuk bergabung ke jaringan radar.
  • Warm-up Writer: Menyiapkan CommandTopic lebih awal agar tidak terjadi jeda (delay) saat perintah pertama dikirim dari dashboard.
async function initializeDDS() {
    opendds.load(path.join(IDL_BIN_DIR, 'RadarTrack', 'libRadarTrack'));
    const p0 = getParticipant(0); // Mendaftar ke DDS Domain 0
    getWriter(p0, 'CommandTopic', 'RadarCommand::Command'); // Warm-up
}

Bagaimana mengatur Pub, Sub, Topic di Gateway

Gateway bertindak sebagai jembatan yang secara dinamis memetakan permintaan HTTP/WebSocket ke entitas DDS (Topic, DataWriter, DataReader) menggunakan Native Binding.

1. Pemetaan Topic Dinamis

Gateway mengikuti standar OMG DDS-WEB di mana domain dan topik ditentukan melalui URL:

// Format URL di Gateway
/domain/:domainId/topic/:topicName/data

2. Registrasi Tipe Data

Agar Gateway mengenali struktur data biner, library IDL harus dimuat saat startup:

// Line 140 - 141 di server.js
opendds.load(path.join(IDL_BIN_DIR, 'RadarTrack', 'libRadarTrack'));

Alur Operasi Pub/Sub di Gateway

Publishing (REST POST) Line 57 - 75

Menerima payload JSON dari aplikasi web dan menerjemahkannya ke biner DDS via DataWriter.

// Mengambil writer yang sesuai topik
const writer = getWriter(participant, topicName, typeName);
// Mengirim data ke jaringan DDS
writer.write(req.body);
Subscription (WebSocket) Line 108 - 119

Mendengarkan data dari DDS dan langsung meneruskannya ke klien web yang terhubung.

const reader = participant.subscribe(topicName, typeName, subQos, (r, info, sample) => {
    if (info.valid_data && ws.readyState === ws.OPEN) {
        ws.send(JSON.stringify(sample)); // Konversi otomatis ke JSON
    }
});

Manajemen Lifecycle & Cleanup

Berbeda dengan aplikasi C++, di Node.js kita harus memastikan unsubscribe dipanggil saat WebSocket ditutup untuk menghindari kebocoran memori:

// Line 125 di server.js
ws.on('close', () => {
    participant.unsubscribe(topicName, reader);
});

Bagaimana mengatur QoS di Gateway

Berbeda dengan Frontend, Gateway memiliki kendali penuh atas kebijakan DDS QoS karena berinteraksi langsung dengan native binding OpenDDS.

Implementasi Nyata di Project

Pengaturan QoS dikonfigurasi secara spesifik per-topik di dalam file:
gateway-ddsweb/server.js

DataWriter QoS (Command) Line 43 - 50

Mengatur agar perintah kontrol bersifat Reliable dan Transient Local.

const qos = {
    DataWriterQos: {
        reliability: { kind: 'RELIABLE_RELIABILITY_QOS' },
        durability: { kind: 'TRANSIENT_LOCAL_DURABILITY_QOS' }
    }
};
DataReader QoS (Radar Tracks) Line 93 - 105

Mengatur agar streaming data radar menggunakan Best Effort untuk latensi terendah.

const subQos = {
    DataReaderQos: {
        reliability: { kind: 'BEST_EFFORT_RELIABILITY_QOS' },
        history: { kind: 'KEEP_LAST_HISTORY_QOS', depth: 1 }
    }
};

Note: Konfigurasi TRANSIENT_LOCAL pada Gateway memastikan bahwa jika simulator C++ dinyalakan belakangan, ia akan langsung menerima status "START" terakhir yang dikirim dari Dashboard.

Bagaimana mengatur dan mengkompile IDL di Gateway

Berbeda dengan Frontend yang men-generate TypeScript, Gateway mengkompilasi IDL menjadi Shared Object (.so) biner agar dapat dimuat oleh mesin native OpenDDS.

⚠️ Mekanisme Native Binding

Gateway menggunakan node-opendds yang memerlukan library biner (.so) untuk melakukan introspeksi data secara dinamis.

  • Proses Dua Tahap: Pertama, IDL diproses oleh opendds_idl (via MPC). Kedua, hasilnya dikompilasi menggunakan make (G++).
  • Otomatisasi Wrapper: Karena perintah aslinya cukup panjang, kami menyediakan script scripts/idl-compiler.js yang mengotomatisasi seluruh alur build tersebut.

1. Struktur & Master Workspace (MWC)

MWC digunakan untuk menggabungkan beberapa proyek IDL agar dapat dikompilasi secara massal dalam satu perintah.

// gateway_idl.mwc
workspace {
  RadarTrack/RadarTrack.mpc
  RadarCommand/RadarCommand.mpc
}

2. Konfigurasi Proyek (MPC)

Setiap folder IDL memiliki file .mpc yang mendefinisikan bagaimana library biner harus dibangun.

// RadarTrack.mpc
project: dcpslib {
  TypeSupport_Files {
    RadarTrack.idl
  }
}

Mengenal MPC (MakeProjectCreator)

OpenDDS menggunakan MPC untuk mengotomatisasi pembuatan Makefile yang kompleks. Berikut adalah komponen kuncinya:

  • project: dcpslib: Menggunakan template dcpslib yang sudah menyertakan dependensi standar OpenDDS untuk library biner.
  • TypeSupport_Files: Bagian paling krusial. Memberi tahu sistem bahwa file IDL tersebut harus diproses oleh opendds_idl untuk menghasilkan kode sumber C++ (TypeSupport) sebelum dikompilasi menjadi library .so.
  • Custom Output: Secara default, MPC akan menghasilkan library dengan awalan lib (misal: libRadarTrack.so), yang kemudian akan dimuat oleh Node.js via opendds.load().

Workflow Penambahan IDL Baru

Jika Anda ingin menambahkan modul data baru (misal: Weather), ikuti alur kerja berikut agar terintegrasi dengan sistem build otomatis:

  1. Buat Folder Modul: Buat folder baru di dalam gateway-ddsweb/idl/ (Contoh: idl/Weather/).
  2. Siapkan File IDL: Letakkan file Weather.idl di dalam folder tersebut.
  3. Buat Konfigurasi MPC: Buat file Weather.mpc di folder yang sama (copy dari modul lain dan sesuaikan namanya).
  4. Update Master Workspace (MWC): Daftarkan path MPC baru Anda ke dalam file idl/gateway_idl.mwc agar sistem build mengenalnya.
  5. Eksekusi Build: Jalankan script compiler untuk menghasilkan library .so.

Eksekusi Build Otomatis

Setelah langkah di atas selesai, jalankan perintah ini di root folder gateway-ddsweb:

node scripts/idl-compiler.js

Full Source Code: scripts/idl-compiler.js (Gateway)

Script ini bertanggung jawab memicu generator MPC dan compiler Make secara berurutan:

/**
 * GATEWAY IDL Compiler & Builder
 * -----------------------------------------
 * Dirancang untuk mengotomatisasi kompilasi IDL OpenDDS menjadi
 * shared library (.so) yang dapat dimuat oleh Node.js.
 */

const { execSync } = require('child_process');
const path = require('path');
const fs = require('fs');

const IDL_DIR = path.resolve(__dirname, '../idl');
const MWC_FILE = 'gateway_idl.mwc';

console.log('-----------------------------------------');
console.log(' [SYSTEM] Gateway IDL Builder ...');
console.log('-----------------------------------------');

try {
    // Cek Environment
    if (!process.env.DDS_ROOT || !process.env.ACE_ROOT) {
        throw new Error('DDS_ROOT atau ACE_ROOT tidak ditemukan.');
    }

    process.chdir(IDL_DIR);

    // 1. Generate Makefiles menggunakan MPC
    console.log(' [MPC] Generating GNUACE Makefiles...');
    execSync('$ACE_ROOT/bin/mwc.pl -type gnuace ' + MWC_FILE, { stdio: 'inherit' });

    // 2. Compile menggunakan Make
    console.log(' [MAKE] Compiling Shared Libraries...');
    execSync('make', { stdio: 'inherit' });

    console.log('-----------------------------------------');
    console.log(' [SUCCESS] All IDLs compiled successfully.');
    console.log('-----------------------------------------');

} catch (error) {
    console.error(' [ERROR] Compilation failed:');
    console.error(error.message);
    process.exit(1);
}
